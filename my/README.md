# Elsaad ERP

تطبيق سطح مكتب عربي من دون React، مبني باستخدام Electron وTypeScript وVite. الواجهة تعمل داخل نافذة Electron، ويُحفظ ما يُدخله المستخدم في قاعدة SQLite محلية ضمن مجلد بيانات التطبيق.

## التشغيل

يتطلب Node.js 22.12 أو أحدث وnpm.

```powershell
npm install
npm run dev
```

يفتح `npm run dev` نافذة Electron ويشغّل خادم Vite محليًا للتطوير. لتدقيق TypeScript وبناء ملفات التشغيل:

```powershell
npm run typecheck
npm run build
npm start
```

في التثبيت الجديد، لا توجد كلمة مرور مدير افتراضية. عند التشغيل الأول، يطلب التطبيق تعيين كلمة مرور قوية لمدير النظام قبل إتاحة بيانات التطبيق. يجب أن تتكون من 12 حرفًا على الأقل وتشمل حرفًا كبيرًا وصغيرًا ورقمًا ورمزًا؛ لا يمكن تخطي الإعداد أو إعادة تشغيله بعد إنشاء الحساب.

عند فتح قاعدة بيانات قديمة تحتوي حساب المدير الافتراضي `Admin123`، تبقى الحسابات والبيانات كما هي، لكن يُمنع الدخول حتى تغيير كلمة المرور الافتراضية. بعد التغيير، يسجل المستخدم الدخول بكلمة المرور الجديدة. قواعد البيانات التي تحتوي حسابات قائمة بكلمات مرور أخرى لا يُعاد إعدادها ولا تتغير بيانات الحسابات الموجودة.

## حزمة Windows

يتطلب إصدار Windows شهادة توقيع Authenticode صالحة وموثوقة من جهة إصدار معتمدة. احفظ شهادة PFX/P12 خارج المستودع، ومرر مسارها المطلق في `CSC_LINK` وكلمة مرورها في `CSC_KEY_PASSWORD` كسرّين مؤقتين في بيئة الإصدار؛ يستخدم `electron-builder` هذين المتغيرين للتوقيع. لا تضع الشهادة أو كلمة المرور في ملفات المشروع أو سطر أوامر محفوظ أو سجلات CI.

تستخدم حزمة Windows الأيقونة متعددة الأحجام `build/icon.ico` لكل من ملف التطبيق والمثبّت ومزيل التثبيت ورأس معالج التثبيت، وتُنشئ اختصارات سطح المكتب وقائمة Start باسم `Elsaad ERP`. تأتي بيانات الشركة والمنتج والوصف والإصدار من بيانات الحزمة (`author`, `description`, `version`, `productName`)، ويُضبط الناشر القانوني إلى `Mohanda Saad`. يجب أن يطابق اسم الناشر الاسم القانوني في شهادة توقيع الإصدار؛ إذا كانت شهادة المؤسسة تستخدم اسمًا قانونيًا مختلفًا، حدّث `build.win.publisherName` ليطابقها حرفيًا قبل الإصدار. يتوقف فحص ما قبل الإصدار إذا كانت الأيقونة متعددة الأحجام أو أي من إعدادات بيانات المنتج والاختصارات غير مكتملة.

```powershell
$env:CSC_LINK = 'C:\Secure\elsaad-code-signing.pfx'
$securePassword = Read-Host 'Certificate password' -AsSecureString
$passwordPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($securePassword)
try {
  $env:CSC_KEY_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($passwordPointer)
  npm run dist:win
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($passwordPointer)
  $securePassword.Dispose()
  Remove-Item Env:CSC_KEY_PASSWORD -ErrorAction SilentlyContinue
  Remove-Variable securePassword, passwordPointer
}
Remove-Item Env:CSC_LINK -ErrorAction SilentlyContinue
```

شغّل الأمر على Windows بعد تثبيت اعتماديات المشروع. يفشل الإصدار قبل البناء عند غياب الشهادة أو كلمة المرور، أو إذا كان ملف الشهادة داخل المستودع. ينشئ المثبّت وملفات التطبيق في مجلد فريد تحت `release`، ثم يتحقق من صلاحية توقيع Authenticode للمثبّت ولكل ملفات EXE الخاصة بالتطبيق؛ أي ملف غير موقع أو سلسلة ثقة غير صالحة توقف الإصدار. يجب أن تكون الشهادة صالحة لتوقيع الشيفرة وأن تثق بها بيئة البناء. في CI، خزّن الملف وكلمة المرور في مخزن الأسرار ومررهما وقت المهمة فقط، دون طباعتهما أو تضمينهما في ملفات البناء.

## حالة الوظائف والبيانات

تتضمن النسخة الحالية تنقلًا بين أقسام النظام، ولوحة مؤشرات بأعداد سجلات SQLite الفعلية، وإضافة السجلات وتعديلها وحذفها والبحث فيها وتصديرها إلى CSV. لا تُزرع بيانات تجريبية. حقل القيمة اختياري ويُحفظ كنص كما أدخله المستخدم؛ لا يُستخدم لحساب رصيد أو قيد محاسبي.

تحتوي قائمة المشاريع على لوحتي «داشبورد العقارات» و«داشبورد المشاريع». تعرضان سجلات المشاريع، وأعداد فواتير البيع والمرتجعات وأوامر التشغيل المعتمدة وأسطر الإيرادات/المصروفات المرحلة، مع فلاتر مشروع وفترة وطباعة. لا يعرض النظام مبالغ موحدة أو أرباحًا أو تحصيلات أو أقساط أو عمولات أو وحدات عقارية؛ لا تحتوي المستندات/القيود الحالية على عملة موثقة أو ربط مالي بالمشروع، كما لا توجد جداول للوحدات والأقساط والتحصيل والتسليم. لذلك تظهر هذه المؤشرات «لا توجد بيانات كافية» بدل تقديرات. فواتير المشتريات المسودة تُعرض كتنبيه ولا تُحتسب تكاليف.

تحتوي المبيعات على صفحات المقايسة وأمر التشغيل والمستخلص والفاتورة، مع مستندات SQLite مترابطة وبنود منقولة واعتماد وبحث وتعديل المسودات وحذفها وطباعتها. يتطلب ترحيل الفاتورة عميلًا مرتبطًا بحساب ذمم، وبندًا مرتبطًا بصنف بيع نشط وحساب إيراد صالح؛ يسجل الاعتماد مدين ذمم العميل ودائن إيراد الصنف في معاملة واحدة. لا تخصم الفاتورة المخزون؛ يُنشأ إذن صرف مستقل مرتبط بالفاتورة ويخصم الكمية بالمتوسط المرجح، مع مدين تكلفة البضاعة المباعة ودائن المخزون. يمكن إلغاء الفاتورة بعد إلغاء الأذون والمرتجعات التابعة، ويُنشأ القيد العكسي في أول تاريخ مفتوح. لا تُطبق الضرائب أو العملات الأجنبية. يسمح النظام بفاتورة نشطة واحدة لكل مستخلص؛ لم يُنفّذ تقسيم المستخلص إلى فواتير جزئية.

أضيف إلى المبيعات دليل محلي للعملاء ومجموعاتهم، مع البحث والتعديل والتعطيل، ومنع الحذف عند وجود ارتباطات. استيراد/تصدير العملاء متاح بصيغة CSV المتوافقة مع Excel فقط (وليس ‎.xlsx)، والطباعة متاحة من القائمة. تعرض لوحة المبيعات مجاميع الفواتير والمرتجعات المعتمدة حسب البيانات والفلاتر، دون أرقام افتراضية؛ المستندات القديمة غير المرتبطة بمعرّف عميل لا تُطابق تلقائيًا بالاسم. مرتجع البيع المعتمد يعكس الإيراد ويخفض ذمة العميل؛ لا ينشئ ردًا نقديًا ولا يعيد المخزون تلقائيًا، إذ لا يوجد حقل ربط بين المرتجع وإذن الصرف الأصلي حتى الآن.

يتضمن قسم المشتريات لوحة مؤشرات وقوائم فواتير ومرتجعات وموردين ومجموعات موردين محلية. تتطلب فاتورة الشراء صنفًا مخزنيًا ووحدة أساسية وحساب مورد دائنًا؛ ويُشترط تطابق حساب الشراء مع المخزون، ثم يرحّل الاعتماد مدين المخزون ودائن المورد دون زيادة كمية المخزون. إذن الاستلام المعتمد يزيد المخزون بسعر الفاتورة فقط بعد اعتمادها، وإلغاءه يعكس الحركة. إلغاء الفاتورة يعكس القيد بعد إلغاء الاستلامات والمرتجعات التابعة. اعتماد مردود الشراء ما زال محجوبًا إلى حين ربطه ببند استلام محدد وتنفيذ فحص المتوسط المرجح. لا تُحتسب الضريبة أو الخصومات. لا تتوفر مطابقة دفعات الموردين بالفواتير أو أعمار المستحقات، لذا تظهر هذه القيم «غير متاح»؛ اختيار خزينة أو بنك في المسودة لا ينشئ دفعة. يمكن تصدير الموردين واستيرادهم بصيغة CSV المتوافقة مع Excel فقط؛ لا تدعم الحزم الحالية ملفات ‎.xlsx.

تحتوي صفحة الخزائن والبنوك على سجلات تعريفية منفصلة مرتبطة بحسابات أصول من دليل الحسابات، مع البحث والتعديل والتعطيل. رصيد أول المدة وتاريخه والعملة بيانات تأسيسية محفوظة بدقة ولا تنشئ قيدًا أو حركة مالية؛ وتُعرض العملات منفصلة دون جمعها. بعد تسجيل قيود على الحساب المرتبط، تُحمى هوية السجل وعملته ورصيد تأسيسه من التعديل. لم تُنفذ بعد سندات القبض أو الصرف أو التحويل المالي، ولا يتغير الرصيد من عمليات تعريف الخزينة أو البنك.

تتضمن المرحلة الأولى للمخزون إدارة الأصناف ووحدات القياس والمخازن، وأرصدة افتتاحية اختيارية محفوظة مرة واحدة لكل زوج صنف/مخزن. الوحدات لا تدعم التحويل التلقائي، والحسابات المرتبطة تختار اختياريًا من دليل الحسابات الحالي. تُرفض الأكواد والباركود المكررة، وتُمنع عمليات الحذف عند وجود ارتباطات تاريخية مع إتاحة التعطيل. حقول الضريبة تُحفظ كقيمة وصفية اختيارية فقط ولا تُطبق على المستندات حتى تهيئة إعدادات الضرائب.

تتضمن المخزونات سجل حركات موحدًا وأذونات استلام وصرف وتحويل. أرصدة الأصناف لكل مخزن تُحسب من الأرصدة الافتتاحية والحركات المعتمدة، والحفظ كمسودة لا يغيّرها. اعتماد الصرف والتحويل والاستلام يتم داخل معاملة SQLite مع فحص الرصيد ومنع التكرار؛ إلغاء المستند المعتمد يسجل عكسًا ولا يمحو الحركة الأصلية. تكلفة الصرف تُحتسب بمتوسط تكلفة المخزن وقت الاعتماد؛ الصرف الداخلي/المشروعات يقيد المصروف مقابل المخزون، وصرف البيع المرتبط بفاتورة معتمدة يقيد تكلفة البضاعة المباعة مقابل المخزون ويمنع تجاوز كمية الفاتورة. التحويل بين المخازن ينقل التكلفة نفسها دون قيد محاسبي.

تتضمن صفحات المشاريع إدارة بيانات المشروع وكوده الفريد وتواريخه وحالته ومركز تكلفته، وشجرة بنود أعمال هرمية، وسند صرف مواد مرتبطًا بمشروع وبند أعمال. تُرحّل سجلات المشاريع العامة السابقة مرة واحدة إلى جدول المشاريع المتخصص دون حذف السجلات المصدر؛ التاريخ المفقود يبقى غير محدد. اعتماد سند مواد المشروع يسجل خصمًا ذريًا بدفتر المخزون القائم ويأخذ متوسط تكلفة المخزن وقت الاعتماد (نفس سياسة الصرف الداخلي)، والإلغاء يستخدم حركة عكسية. لا ينشأ قيد محاسبي تلقائي. تمنع علاقات السندات وبنود الأعمال حذف المشاريع المستخدمة، وتُحمى هوية البند بعد استخدامه في حركة. صفحة «وحدات المشروع» توضح أن دليل الوحدات العقارية غير موجود بعد؛ لم تُنشأ وحدات افتراضية أو مبيعات عقارية.

المجلد الذي فُحص قبل التأسيس لم يتضمن مصدرًا للبرنامج الأصلي أو قاعدة بيانات أو صورًا مرجعية ظاهرة أو وصفًا لقواعده المحاسبية. لذلك لا تدّعي هذه النسخة مطابقة دورات المبيعات والمشتريات والمخزون والقيود المحاسبية الأصلية، ولا تحتسب الضرائب أو الأرصدة أو الأقساط. يلزم توفير مخطط بيانات العملاء والأصناف وقواعد المخزون والترحيل قبل استكمال تلك الروابط والوظائف.

قفل Electron يمنع تشغيل أكثر من نسخة من التطبيق في الوقت نفسه على الجهاز. هذا ليس ترخيصًا يربط قاعدة البيانات بجهاز واحد، ولا يمنع نسخ ملفاتها إلى جهاز آخر.

## قاعدة البيانات والخصوصية

يستخدم التطبيق SQLite المدمج في Node.js الذي يأتي مع Electron، ولا يحتاج إلى خدمة قاعدة بيانات خارجية. تبقى قاعدة البيانات في مجلد بيانات Elsaad ERP المحلي، ولا يُرسل التطبيق السجلات إلى خادم.

تضم صفحة الإعدادات المظهر المحفوظ وبادئة قابلة للتخصيص لأرقام الفواتير الجديدة، وسياسات التشغيل الحالية للقراءة، وبيانات الشركة المستخدمة في عناوين التقارير. تبقى أرقام المستندات السابقة دون تغيير. يمكن ضبط النسخ الاحتياطي الدوري والاحتفاظ، وإنشاء نسخة SQLite مستقلة والتحقق منها قبل الاستعادة؛ تنشأ نسخة أمان قبل أي استعادة.

بعد تسجيل الدخول، يفتح التطبيق أول قسم يملك المستخدم صلاحية عرضه بدل افتراض صلاحية لوحة المؤشرات. إذا لم تُمنح للحساب أي صلاحية عرض، تظهر له رسالة واضحة مع خيار تسجيل الخروج. تعرض هوية المستخدم المسجل حاليًا في الشريط العلوي.

## البنية

- `electron/`: العملية الرئيسية وواجهة IPC الآمنة.
- `src/`: واجهة RTL وصفحات الأقسام والمكوّنات والأنماط والأنواع المشتركة.
- `public/assets/`: الأصول الثابتة.
- `dist/` و`dist-electron/`: نواتج البناء المحلية، وغير مضمّنة في التحكم بالمصدر.
